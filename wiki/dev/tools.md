## Micro

- Micro uses its default colourscheme (`dotfiles/micro/settings.json`).
- Micro rewrites files atomically, so the whole directory is linked.
  `dotfiles/micro/.gitignore` is an allow-list, so only `settings.json` is
  tracked. Backups, history and `bindings.json` stay local.

## Zed

`settings.json` sets Berkeley Mono and the font sizes (UI 16, buffer 14);
Zed's default theme follows the system light/dark mode. Zed follows KWin's
150% scale itself. Zed rewrites its settings file, so the whole directory is
linked. `$EDITOR` is `zeditor --wait`, so Git and other callers block until
the tab is closed.

## VS Code

Plain package; it follows KWin's scale on Wayland. `settings.json` sets
Berkeley Mono. Extensions stay in `~/.vscode/`, outside Git.

## Lazygit

No managed config; Lazygit writes its own `~/.config/lazygit/` on first run.

## SSH

Home Manager generates `~/.ssh/config`, which includes `~/.ssh/config.local`.
Hosts tied to personal accounts go in that local file, outside Git, as plain
OpenSSH blocks (`Host`, `HostName`, `User`). Shareable hosts and the user's own
LAN hosts go in `programs.ssh.settings` in `modules/home/ssh.nix`, so a
reinstall keeps them. The Proxmox host is declared there as `pve`.

## Codex via codex-lb

`codex` is a wrapper (`modules/home/apps/codex.nix`) that sends every request
through codex-lb, a load balancer for ChatGPT accounts running on pve, reached over HTTPS
through its reverse proxy. Its address comes from the private pve repo's registry.
It reads the API key from the agenix secret `codex-lb` (`hosts/draba/codex-lb.nix`)
and adds the provider with `-c` flags, so `~/.codex/config.toml` stays Codex's
own file (trust levels, model choice). The address and settings follow
codex-lb's client setup for Codex with API key auth.

- Only the `codex` CLI is routed; an IDE extension uses its own binary.
- New key: create it in the codex-lb dashboard, then edit the secret
  ([Secrets](../security/secrets.md#edit-or-create-a-secret)) and rebuild.
- Check the route: `codex exec "Reply with OK only."`, then the dashboard's
  request log shows it.
- Bypass it once: `nix run nixpkgs#codex` (direct to OpenAI).

## Agent workflows

Coding agents read `AGENTS.md` (Claude Code via `CLAUDE.md`) and use the skills
in `.agents/skills/` for commits, rebuilds, troubleshooting, packaging, new
hosts and docs. The routing table in [AGENTS.md](../../AGENTS.md#skill-routing)
says which skill handles which task.

Outside this repo, agents read one global file: `dotfiles/agents/AGENTS.md`,
linked to `~/.claude/CLAUDE.md` (Claude Code) and `~/.codex/AGENTS.md` (Codex).
It covers how to work on this NixOS machine, how to reach pve, and the
rules for changes there: read-only by default, explicit approval for each
change, and named confirmation for high-risk operations. These are
instructions, not enforcement; no permission rule blocks `ssh pve`. The
link points into the repo, so edits apply at once, without a rebuild. The repo
is public: the file holds no IP addresses, accounts or secrets.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| Micro settings not saved to Git | expected for ignored files. Extend the allow-list in `dotfiles/micro/.gitignore` |
| nixd shows no completions | editor not pointed at nixd; `nix develop` provides it too |
| `git commit` returns at once with an empty message | `$EDITOR` lacks `--wait`: `echo $EDITOR` |
